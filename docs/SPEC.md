# Спецификация: SIGame Lounge для Roblox

## Цель

Сделать игру для компании в Roblox, которая сохраняет классическую механику SIGame, но превращает её в уютную мультяшную lounge-сцену: ведущий находится во главе стола, игроки сидят вокруг, отвечают со своих устройств, общаются и развлекаются между вопросами.

## Пользовательский сценарий

1. Каждый игрок при входе выбирает роль кнопкой: «Игрок» или «Ведущий».
2. В комнате может быть только один ведущий; если роль уже занята, остальные выбирают игрока.
3. Ведущий может отказаться от роли в лобби, после чего другой участник сможет выбрать ведущего.
3. Остальные заходят в ту же комнату и выбирают места.
4. Ведущий открывает каталог, ищет пак и запускает его или включает голосование.
5. На поле ведущий выбирает клетку.
6. Вопрос отображается в центре стола: текст, картинка или звук.
7. Игроки нажимают кнопку ответа, затем вводят текст или выбирают карточку.
8. Ведущий видит ответы, отмечает правильность и начисляет очки.
9. Между действиями игроки используют мемные предметы с cooldown.
10. Ведущий может ограничить нарушителя или отправить его в мультяшную яму на минуту.

## Функциональные требования

### Игровая механика

- классическое поле: категории × стоимость;
- обычные раунды и финальный раунд;
- фальстарт/кнопка ответа;
- один ведущий с правом выбора вопроса и проверки ответов;
- ведущим может стать любой игрок через передачу роли;
- автоматический счёт и ручная корректировка ведущим;
- корректная работа от двух игроков плюс ведущий.

### Ответы

- закрытый индивидуальный TextBox для текстового ответа;
- карточки вариантов для вопросов с выбором;
- быстрые кнопки для «да/нет» и похожих форматов;
- остальные игроки видят только статус ответа, но не чужой текст;
- пользовательский текст фильтруется средствами Roblox до отображения другим игрокам.

### Пакеты

- ведущий может искать паки в каталоге прямо из игры;
- игроки могут просматривать каталог и предлагать пак;
- выбор ведущего или голосование — настройка комнаты;
- принимается исходный `.siq` без ручной конвертации;
- импортёр поддерживает ZIP-структуру с `content.xml`, `Images/`, `Audio/`, `Video/`, `Html/`;
- версии SIGame v4 и v5 — целевой формат первой совместимой версии;
- незнакомые типы вопросов не ломают импорт: импортёр показывает предупреждение и использует безопасный fallback.

### Lounge и социальные действия

- тёплый свет, диваны, стол, место ведущего во главе;
- заказы чая, кофе и кальяна как визуальные/звуковые интеракции;
- вызов мультяшного официанта;
- предметы «помидор», «мемный снаряд» и карикатурная «какашка» с cooldown;
- ведущий может: временно отключить предметы, заглушить игрока, исключить игрока, отправить в яму на 60 секунд.

## Технологический контур

- Roblox-клиент: Luau, native UI, RemoteEvents, сервер авторитетен для игры;
- каталог: локально запускаемый Python HTTP-сервис как первый вертикальный срез;
- импорт `.siq`: ZIP + XML parser на стороне каталога, результат — нормализованный JSON;
- медиа: пользователь загружает оригинальный `.siq`; сервис автоматически извлекает медиа и подготавливает asset manifest. Для Roblox-отображения картинки/аудио должны быть опубликованы как разрешённые Roblox-ассеты;
- онлайн-комната v1: один Roblox-сервер = одна игровая комната, без отдельного matchmaking-сервиса;
- Rojo — источник правды для Luau-файлов.

## Стиль кода

Luau-модули маленькие и предметные; сервер проверяет все действия клиента.

```lua
local function canUseItem(player: Player, itemId: string, now: number): boolean
    local nextUse = cooldowns[player.UserId] and cooldowns[player.UserId][itemId] or 0
    return now >= nextUse
end
```

Python API возвращает предсказуемые JSON-объекты и не доверяет имени/содержимому загруженного архива.

## Тестирование

- Python: `python -m unittest discover -s catalog/tests`;
- импортёр: фикстуры `.siq` v4/v5, повреждённый ZIP, отсутствующий `content.xml`, дубли медиа;
- Luau: unit-тесты игровых правил и cooldown;
- Studio: ручной multi-client playtest, ведущий + 2 игрока;
- финальная проверка: поле, выбор вопроса, ответ, проверка, очки, каталог и модерация.

## Границы

- Всегда: сервер авторитетен; все пользовательские тексты фильтруются; внешние HTTP-источники allowlist; импортёр ограничивает размер и тип файлов.
- Спросить перед: публикацией игры, загрузкой ассетов в Roblox, подключением платного облака, изменением формата `.siq`.
- Никогда: не коммитить токены, не загружать произвольные сторонние скрипты в Roblox, не встраивать чужие мемные медиа без проверки лицензии/прав.

## Критерии успеха MVP

- ведущий и два игрока видят один и тот же вопрос и счёт;
- ведущий может пройти минимум один полный раунд;
- `.siq` импортируется через каталог без действий пользователя по конвертации;
- текстовые вопросы работают полностью, медиа получают понятный статус подготовки;
- каталог умеет поиск и установку/выбор пака;
- мемный предмет соблюдает cooldown, а ведущий может его отключить;
- проект собирается через Rojo и имеет проверяемые тесты.

## Известные ограничения

Roblox ImageLabel ожидает Roblox image/decal asset, а не произвольный URL. Поэтому «без конвертации» означает отсутствие ручной конвертации для игрока: каталог сам импортирует `.siq`, но публикация медиа в Roblox остаётся отдельным контролируемым этапом asset pipeline.
